# 知序 · 计算机成长空间

这是围绕「技术成长 + 项目实践 + 求职面试 + 考研升学」制作的第一版可交互网站原型。

## 专业学习与求职升级（2026-10-22）

模块结构、页面要素、数据字段与兼容改造清单详见 [UPGRADE.md](./UPGRADE.md)，依次按这三个层次组织。

- `#growth`：前端、后端、算法、数据、系统与基础架构、人工智能、安全、测试、游戏开发九大专业方向；每方向包含分阶段任务、带依赖和优先级的技能树、业务工程项目与验收标准、原创面试解析和关联资源。
- `#roles` / `#role?role=frontend-engineer`：15 个岗位的能力模型、校招与社招目标、JD 能力词解释、成果要求、简历表达与面试准备。能力目标是平台编辑基线，具体团队要求应以实际 JD 为准。
- `#assessment`：54 个技能的自评入口与 27 道客观知识题，保留独立答题记录，输出已识别差距、未评估项和证据覆盖率。
- `#plan`：依据目标岗位、招聘类型、测评结果与每周可用时间生成按依赖排序的任务，包含阶段目标、工程验收、任务进度与导出；调整计划保留已完成记录。

诊断使用透明的本地规则。知识题只能提供有限知识信号，最高对应 L2；工程交付和方案设计的 L3/L4 需要进一步作品评审。自评、任务勾选与客观答题分别保存，未评估项保持未知。匹配显示已测部分达成度、覆盖率及未知区间，不代表录取概率。

新增 `professional-data.js`（内容）、`growth-core.js`（诊断和排程）、`growth-ui.js`（页面和本地交互）、`growth.css`（主题与响应式样式）。沿用原生 ES Modules、现有 hash 路由和静态服务；成长记录独立保存在 `zhixu-growth-v1`，原学习、收藏及面试记录保持原有键与结构。暂无账户、跨设备同步、服务器评审或在线大模型调用。

验证：`npm test` 覆盖原有逻辑与新增内容、诊断边界、未知值、状态清洗、依赖排程及记录恢复；`npm run test:growth` 覆盖新增页面交互，`npm run test:growth:layout` 检查全部新方向与岗位页面的双主题、响应式布局。已有浏览器测试继续保留。运行中的旧静态服务需重启，以加载新的公开文件白名单。

需要 Node.js 20 或更新版本。网站本身不依赖第三方运行时库。


## 数据和服务边界

- 用户记录保存在浏览器 localStorage，尚无注册、登录、数据库或跨设备同步。
- 帮扶需求是本地草稿，不会发送给导师；没有真实预约、排期、支付或在线咨询。
- 资料库是外部资源导航，不是本站托管的完整课程、题库或教材。
- 408 提纲是学习组织示例，不代替报考年份的考试大纲和院校通知。
- 复习草案采用固定比例，是可调整的起点，不是基于诊断的个性化推荐。
- 面经摘要来自公开用户自述，本站无法独立验证实际面试过程；历史样本不代表当前招聘流程。原创练习和公司场景为编辑建议。
- 外部网站内容、可访问性和课程条件可能变化，发布前需要做人工资源审核。
